# 设备检查与解决方案

公共层按机型选择 `SolutionProvider`，不在 UI 中判断设备型号。机型 package 的
`SolutionHooks() []installer.SolutionHook` 声明该机型的全部检查项，Hook 根据所选镜像决定是否适用。
未实现 Hook 的机型保持原流程。

检查 Hook 始终只读，返回问题、指引和可选的 `RepairID`。独立的 `RepairProvider`
注册修复执行器；`PrepareRepair` 重跑检查、确认修复仍适用，再生成只读预览。
用户在独立确认页选择“确认更新”后才调用执行器。回调属于机型源码，不接受外部任意 Shell 脚本。
交互修复与安装共用单实例锁。

## 检查时机与阻断

1. 语言选择后先选择镜像。本地文件完成完整性校验、GitHub 镜像完成下载及校验后，
   才按真实镜像元数据选择安装目标并运行检查；镜像来源页不提供脱离镜像的检查入口。
2. 进入最终写入确认前再次检查。`arm` 从已暂存且校验通过的安装请求恢复镜像上下文后检查。
3. 按声明顺序执行全部 Hook。发现问题或单项失败仍继续后续检查，汇总全部结果；用户取消时停止。
4. 每个 `Issue` 可包含多条 `Solution`，全部展示并支持滚动。仅发现问题或检查失败时自动弹出；
   正常结果直接进入下一步。提醒可继续；阻断问题或检查失败隐藏“继续安装”，动作层也校验。
5. “重新检查”重跑全部 Hook。阻断解除后仍须完成原有的目标写入确认。
   “更换镜像”会清除旧检查结果，重新选择并校验；Esc 退出，不绕过阻断。

`CheckContext` 包含只读根目录、安装目标、已校验的 `Image` 及 `ImagePath`；阶段为
`image-ready` 或 `before-install`。没有镜像上下文时公共检查入口拒绝执行。
`CheckResult.Supported` 区分没有适用检查与现有检查正常，`Checks` 保留每项错误。
文案键对应内置英文、简体中文和繁體中文。

独立命令 `onekvm-installer solution --image /data/OneKVM.img` 先校验镜像，再检查。
交互命令未给 `--image` 时先填写镜像路径；非交互、JSON 和 `--repair` 预检必须指定镜像。
只读命令不依赖安装资格、暂存目录或已挂载的 `/boot`。检查失败或阻断问题返回非零，保留完整结果。

## Pro Desk：SD 镜像的启动条件

仅 `Image.Profile=pro-sd` 运行 SD 检查；eMMC 镜像不读取 SD 卡或提示 SD 启动问题。
先检查 SD 卡是否存在，不存在则提示插卡并阻止继续。存在时检查当前 eMMC 主 SPL；
已匹配 SD 优先固件则通过，否则提供固件修复提醒。未适配的 Pro PCIe/ATX 不套用 Desk 方案。

判断不依赖卡上的旧系统、OneKVM 标记或启动文件，空白卡也能正常检查。
修复预检从所选完整镜像校验 SD U-Boot/ATF，写前再次核对镜像身份、SD CID、eMMC CID 和原固件。
未知原件、缺少差分包或所选镜像不匹配均在写前停止。固件问题为提醒，缺少 SD 卡为阻断。

最终简体中文文案如下，英文与繁體中文随安装器内置。

**标题**：安装 SD 镜像前，请检查启动固件

**说明**：你选择了 SD 卡镜像。当前启动固件未通过 SD 卡优先启动检查，写卡后可能仍进入 eMMC 系统。请选择下方“启用 SD 卡优先启动”。

**安装与启动步骤**：1. 选择下方“启用 SD 卡优先启动”，核对更新范围后确认。

2. 更新完成后重新检查，再继续安装所选 SD 镜像。

3. 安装完成后保留 SD 卡并重启。有卡时优先从 SD 卡启动，无卡时使用原厂 eMMC 系统。

**启用 SD 卡优先启动**：选择下方“启用 SD 卡优先启动”。安装器会检查所选镜像与设备，核对更新范围并确认后，才会更新启动固件。

原厂系统和启动配置会保留。更新完成后继续安装 SD 镜像，安装完成后再重启。

**确认页**：将更新设备的启动固件，启用 SD 卡优先启动。原厂系统和启动配置会保留。

更新完成后，有 SD 卡时优先启动卡中的系统；未插卡时使用原厂 eMMC 系统。请核对下方详情，并在更新期间保持供电。

**未检测到 SD 卡**：所选镜像需要写入 SD 卡，但设备未检测到可用的 SD 卡。

**插卡指引**：请将 SD 卡插入设备卡槽，再选择“重新检查”。若仍未检测到，请重新插拔或更换 SD 卡。

确认页同时列出目标 eMMC、CID、128 KiB 主 SPL 的写入范围和源／目标哈希，默认选中“返回”。
修复使用固定哈希的内置差分包，仅写入主 SPL，写后回读并核对其余前 24 MiB 和 boot0/boot1；不自动重启。
更新后重新检查，再继续安装所选 SD 镜像。测试支持只接受已验证的 Pro Desk 原固件哈希。

只读修复预检：

```sh
onekvm-installer solution --image /data/OneKVM.img --repair pro.sd-boot.firmware --json
```

差分执行器边界见 [SPL 二进制差分方案](bootloader-delta.md)。
