# Pro SPL 二进制差分方案

可以使用标准 `BSDIFF40` 分发 **完整已签名原包 → 完整已签名目标包** 的差分。
更新时先在内存中重建完整目标，校验成功后才写主 SPL；不在 eMMC 上逐条打补丁。
差分包括目标包的签名头，设备不需要私钥或现场重新签名。

测试安装器已实现内置差分包的完整内存重建、写前检查和主 SPL 写入／回读。
写入必须由用户在解决方案页面单独确认，检查与 `--repair` 预览均不写入。
这仍是受限原固件哈希的测试支持，不代表通用更新包已发布。

## 已验证的输入与输出

| 项目 | 原厂包 | SD 优先目标包 |
| --- | --- | --- |
| 大小 | 131,072 字节 | 131,072 字节 |
| SHA-256 | `cdd8f8efd712cd40fa400d782b54dbdaba0b393895b99bd9c030a582aa7e4775` | `443d7f677a72d8123a51b9cb47955c7cac89d8170fcc69cb9a7bede6aac518a4` |
| SPL 载荷大小 | 47,248 字节 | 44,380 字节 |

`bsdiff4 1.2.6` 生成的补丁为 **24,330 字节**，SHA-256 为
`5d8712e5f28651e24133007aaf5ffe70c740c3434d3220b090fa7ae405cf2f7d`。
目标整包 gzip-9 为 104,613 字节，差分包在本例中明显更小。

原包和目标包共 42,650 字节不同，其中包头 266 字节、SPL 代码区域
42,384 字节。`0xcc00..0x20000` 的 EIP 固件和填充逐字节一致；两包的公钥相同，
包头校验、载荷校验和 RSA SHA-256 签名均验证通过。差分重建结果与目标原件
逐字节一致。此验证只读取现有 OE/kas 产物，没有刷写设备。

原件来自 105 的已核对原厂主 SPL，目标为 105 已完成冷／暖启动验证的最终包。
不能把该差分包套用于其他原厂 SPL 哈希或未验证机型；固件签名验证也不代替
对目标设备安全启动策略的适配。

## 执行器边界

1. 通过机型 Hook 识别设备、原 SPL 和安全启动条件，使用可信发布清单选择
   对应差分包。已经是目标版本时跳过更新；不匹配任何已支持原件时停止。
2. 读取主 SPL 的完整 128 KiB，在应用差分前校验源 SHA-256 和差分包完整性。
   每个源哈希提供独立差分，不能模糊匹配版本或强制应用。
3. 在内存中重建长度受限的完整目标，核对目标 SHA-256、包结构、校验和、
   受信公钥及签名。原有 EIP 区域必须保持一致；不能运行不受限的通用解码器
   将补丁直接输出到块设备。
4. 展示固件写入范围并由用户确认，只写 eMMC 用户区偏移 0 的 128 KiB 主 SPL，
   同步后完整回读校验。保留备用 SPL、DDR 参数、eMMC 原厂 U-Boot、ATF、
   OP-TEE、环境、系统分区及 boot0/boot1。
5. 同时确认 SD 卡包含匹配的 SD U-Boot 和 ATF；仅更新 SPL 不能让缺少这些
   文件的镜像启动。写后由用户选择重启时间。

差分减少下载大小，不使 eMMC 写入具备原子性，也不增加断电保护。
`boot-rom-test.bin` 仍是 ROM-SD 实验恢复包，不能作为 eMMC 差分目标。

当前原厂 1.0.15 另有独立差分：源 `c1db005b2d61a5ed8627c70e659b5274a5d87a4d97daac356646d53b63dd44d6`，
补丁 24,341 字节，SHA-256 `22e3c1adeb1a2bc8a99e5a1fb7aaec4d7fcb2ef59c4c9225d8f5f0f245be0c26`。
目标哈希同上，EIP 区域一致，Go 解码器完整重建与故障注入的有界写入测试已通过。
差分文件随安装器源码放在 `internal/machines/nanokvmpro/firmware/`，由 Go
embed 集成到 arm64 发布包；缺少或哈希不匹配这些已固定哈希的包时，修复停止。
